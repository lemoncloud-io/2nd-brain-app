# #64 이후 깨진 e2e 전제 3건 — 시맨틱 제거·툴팁 제거·체크박스→단추

## Context

#64(문구·흐름 개선)와 10/8 시맨틱 검색 제거가 화면·동작을 바꿨는데, 따라가야 할 e2e 스펙 4개가
그대로 남아 main 에서 빨갛게 됐다: `chat` (후속답 refs 0건), `m1-flow` (브랜치 툴팁·`거절:` 문구·체크박스),
`import-vault` (로그아웃 상태 받기 단추), `graph-select` (코너 클릭 빗나감 — 이건 별개 원인).

## Findings

- 후속 질문 `더 알려줘` 는 키워드 검색에서 0건이다(재현 스크립트로 대조: `[]` vs 키워드 포함 질문 3건).
  10/8 시맨틱 제거 전에는 의미 검색이 근거를 실어 줘서 `chat-refs` 가 2묶음이 됐다.
  스펙의 전제("Read 없이도 칩이 둘이면 검색이 실어 준 것")는 키워드 전용 세상에서 거짓이다.
- `IngestSection` 의 브랜치 툴팁(`detailTitle`)과 결과 문구 `거절: <slug>`, 승인 체크박스는 #64 가
  지웠다(브랜치명 비노출·`이번에 넣지 않은 페이지:`·승인/거절 단추). 스펙만 옛 문구를 붙들고 있었다.
- `import-vault` 의 "로그아웃 상태에서 받기 → 로그인 필요 오류" 경로는 #64 가 단추를 잠그면서
  UI 에서 도달 불가해졌다. 도달 불가 경로는 스펙에서 빼고, 잠김+사유 표시를 단언한다.
- `graph-select` 코너 클릭 빗나감은 화면 탓이 아니라 타이밍+기하 문제다:
  날아가기(1100ms) 도중 클릭은 점을 맞히고, `after:` hit-area 확장은 옆 칸 클릭을 가로챈다.
  탐침 정지로 카메라를 기다리고, 크기 조절 띠는 시각 크기 그대로 둔다(키보드가 접근성을 맡는다).

## Decisions

- 후속 질문은 키워드가 걸리는 문장으로 묻는다(`keep 페이지에 대해 더 알려줘`) — resume 경로와
  근거 2묶음을 그대로 검증한다. 타임아웃 늘리기는 결정적 0건이라 기각했다.
- 지운 동작을 단언하는 스펙은 지운다(브랜치 툴팁), 바뀐 문구·역할은 새 말로 단언한다
  (`이번에 넣지 않은 페이지:`, `aria-pressed`, 잠긴 단추+사유).
- `graph-select` 는 탐침 정지(`settleCamera`) 후에 누른다. 고정 sleep 으로 되돌리지 않는다.
- 분리 띠 hit-area 확장은 하지 않는다 — 이웃 클릭을 가로채는 게 확인됐다(패널 리사이즈 핸들 원복).
  분리 띠의 접근성은 `aria-valuetext` + 키보드로 맡긴다.

## Round 2 (같은 밤)

- `loginAndConnect` 가 죽은 건 같은 원인이다 — 시작하기의 팀 저장소 칸도 #64 가 접었다.
  헬퍼가 `start-team-toggle` 을 펴고(`openStartTeam`), `sync-line` 의 시작하기 대조도 같은 길을 탄다.
  `edit-share`·`share-new-docs`·`wiki-share`·`sync-line:84` 가 한 번에 풀렸다.
- 승인 체크박스→단추(`adopt-vault`, `review-defects`, `wiki-share`), MCP 지우기 확인 대화상자,
  `onboarding` 설치 힌트 문구, `sync-line` 상태 줄 문구는 바뀐 화면에 맞춰 단언을 고쳤다.
  지운 동작(툴팁 브랜치명·로그아웃 상태 받기)은 단언에서 빼고, DESIGN.md 툴팁 문장도 같이 고쳤다.
  (`syncDetail` 함수는 #64 가 지웠고 참조가 없다 — 살릴 게 아니라 지운 게 맞다.)
