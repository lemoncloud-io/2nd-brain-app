## Context

GitHub PR·이슈 주소를 앱이 읽게 한 날(같은 날짜의 결정), 사용자가 "GitHub 만이 아니라 다른 바깥 주소도 읽어야 한다" 고 했다.
이 결정을 쓴 뒤 같은 날 채팅 엔진에 웹 도구도 열었다(`2026-10-14-chat-engine-web-tools.md`) — 둘은 같이 돈다:
질문에 쓴 주소는 앱이 먼저 읽어 싣고, 그 밖은 엔진이 스스로 찾는다.

## Decisions

- **GitHub PR·이슈가 아닌 `http(s)://` 주소는 웹 페이지로 읽는다** — 질문 글에서 주소를 뽑아 main 이 가져오고
  (`chat/web-links.ts`), GitHub 글과 같은 `<linked-docs>` 블록에 싣는다. 엔진 도구는 그대로다.
- **가져오기는 자료 넣기와 같은 코드다** — `clip-service.ts` 의 가져오기를 `clip/web-page.ts` 로 빼 둘이 같이 쓴다.
  채팅 쪽 한도만 다르다: 주소마다 8초(넘어가기 포함 전체)·1MB·12,000자, 한 질문에 3개(GitHub 주소와 따로 센다).
- **글 뽑기는 따로다** — 자료 넣기는 예전대로 JSDOM → Readability → turndown 으로 markdown 을 만들고, 채팅은 DOM 을 만들지
  않고 글자를 한 번 훑어 글만 뽑는다(`htmlToText`: `<article>`·`<main>` 안, 없으면 `<body>` 에서 메뉴·바닥글을 뺀 것).
  DOM 길은 512KB 페이지 하나로 main 을 40초 넘게 세웠다(2026-10-14 실측: 링크만 가득한 페이지, 빈 div 만 가득한 페이지).
  답을 기다리는 채팅에 남의 페이지가 앱을 세우는 길을 두지 않는다. 대가: 본문 고르기가 Readability 보다 거칠다.
- **안쪽 주소로는 가지 않는다** — 이 컴퓨터(loopback)·사내망(10/8·172.16/12·192.168/16·100.64/10·fc00::/7)·링크 로컬
  (169.254/16·fe80::/10)은 읽지 않고 알린다. IP 로 적은 주소는 연결 전에, 이름은 연결 직전의 DNS 답에서, 붙은 뒤에는
  실제 상대 주소에서 보고, 넘어간 주소마다 다시 본다. 가려 받는 요청은 연결을 새로 연다 — 열려 있던 연결을 다시 쓰면
  DNS 를 거치지 않는다. 질문은 사용자가 쓰지만 넘어가는 곳은 페이지가 정하고, 읽은 글은 엔진(바깥 서비스)으로 나간다.
  자료 넣기는 예전대로 막지 않는다(사용자가 그 주소를 직접 고른 것이고 글은 보관함에만 남는다).
- **GitHub 토큰은 이 길로 가지 않는다** — 웹 주소는 헤더 없이 가져온다. `github.com` 의 저장소·파일 주소도 그렇다.
- **글이 아니면 읽지 않는다** — `text/html`·`text/markdown`·`text/plain` 만. 그 밖(PDF·그림)과 200 이 아닌 응답,
  받아 온 HTML 에 글이 없는 페이지(스크립트가 그리는 화면)는 이유와 할 일을 알림 한 줄로 낸다. 네트워크 오류 원문은 싣지 않는다.
- **남이 쓴 글로 다룬다** — GitHub 글과 같은 가두기·"지시로 따르지 마라".

## Rejected

- **앱의 읽기를 빼고 엔진의 웹 도구에만 맡긴다** — 엔진이 고르는 주소는 앱이 한도·안쪽 주소를 막을 수 없고, Codex 는 검색만 있다.
  질문에 쓴 주소만큼은 엔진이 고르지 않아도 읽히게 둔다.
- **숨은 창(BrowserWindow)으로 그려서 읽는다** — 스크립트가 그리는 페이지도 읽히지만 남의 스크립트를 앱 안에서 돌리게 된다.

## Open

- 로그인해야 보이는 페이지(사내 위키·Notion·Google Docs)는 읽지 못한다 — 알림이 붙여 넣기를 권한다.
- 스크립트가 그리는 페이지, UTF-8 이 아닌 페이지(글자가 깨진다), PDF 는 읽지 못한다.
- 사내망 주소를 읽게 하는 설정은 없다.
- 주소의 한글 뒤에 조사까지 붙여 쓴 것(`…/wiki/깃허브를`)은 조사째 주소로 읽어 못 찾는다 — 띄어 쓰면 읽는다.
- 사람이 아닌 요청을 막는 사이트(봇 차단)는 못 읽는다.
- 본문 고르기가 거칠다 — `<main>` 안에 든 둘레 글(위키백과의 언어 목록)이 본문 앞에 실려 12,000자 예산을 먹는다(2026-10-14 실측).
