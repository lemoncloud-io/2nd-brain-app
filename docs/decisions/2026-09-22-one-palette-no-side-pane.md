## Context

Obsidian 사용자가 기대하는 편집·탐색 UX 를 채우는 작업. 이전 클론의 12 슬라이스 플랜을 이 체크아웃에서
다시 짜 넷을 이 PR 에 담았다 — 백링크 목록, 리더 ⌘F 찾기, 옆 칸에서 페이지 대조 보기, ⌘P 명령 팔레트.
구현이 끝난 뒤 사용자가 실제로 띄워 보고 둘을 뒤집었다: 옆 칸은 뺐고, 명령 팔레트는 기존 ⌘K 문서 팔레트와
하나로 합쳤다.

## Findings

- 명령 팔레트와 문서 팔레트가 따로 있으면 단축키 둘·상태 둘·양보 규칙 둘이 생긴다. 사용자 관점에서는
  "무언가를 찾아 연다" 한 동작이라 팔레트 하나에 `>` 접두로 갈라 쓰는 편이 배울 것이 적다(VS Code 관례).
- 문서 모드의 결과는 제목 일치만으로는 부족하다 — 검색 뷰가 이미 쓰는 hybrid 검색(키워드+뜻)을 같은
  규칙(150ms 디바운스·늦은 응답 폐기·인덱스 준비 뒤 재검색)으로 붙여야 검색 뷰와 답이 같다. 그 규칙을
  `lib/use-wiki-search.ts` 훅 하나로 빼 두 곳이 공유한다.
- 팔레트가 떠 있는 동안 어떤 단축키를 막을지는 명령마다 `when` 에 적을 수 없다 — 같은 `when` 이 팔레트
  안 명령 목록에도 쓰여, 팔레트 자신을 보면 목록이 빈다. 그래서 훅 한 곳(`allowedWhilePaletteOpen`)이 막는다.
- 전면 2분할은 WikiView 의 live 셀렉터 8곳·액션 45곳이 "현재 페이지" 를 store 한 곳에서 읽는 정본 규칙과
  충돌한다. 얇은 분할(새 store 필드 0, 진입점만)로 줄여 만들었지만, 써 보니 대조할 일이 드물었다.

## Decisions

- ⌘K 하나. 빈 입력은 최근 연 문서, 글자를 치면 제목 일치 즉시 + hybrid 결과가 "본문·뜻" 구역으로 합류,
  맨 끝은 검색 뷰로 넘기는 행. `>` 접두면 명령 모드. ⌘P 는 `>` 를 채운 채 여는 단축키로 남긴다.
- 팔레트가 떠 있을 때 ⌘P 는 모드 전환이 아니라 닫기다 — ⌘K 와 대칭. 전환이 필요하면 `>` 를 치면 된다.
- 옆 칸 대조 보기(슬라이스 03)는 revert. 사용자 판정: 테스트해 보니 쓸모가 없다.
  → 같은 날 목표가 좌우 분할을 다시 열었다(편집되는 오른쪽 칸): `2026-09-22-split-view-returns.md`
- 남은 슬라이스(02·06·08·09·10)는 다음 PR — 사용자 결정.

## Rejected

- 팔레트 둘 유지(⌘K 문서 / ⌘P 명령) — 상태·양보 규칙 중복, 사용자가 둘을 구분해 외워야 한다.
- 명령별 `when` 에 "팔레트 열림" 조건 — 팔레트 목록이 같은 `when` 을 읽어 자기 자신을 비운다.
- 전면 2분할(탭 pane 리팩터) — live 필드 정본 규칙과 충돌, 얇은 분할조차 쓸모가 확인되지 않아 뺐다.
- 팔레트 hybrid 결과를 별도 호출 규칙으로 — 검색 뷰와 답이 갈린다. 훅 공유로 대체.

## Open

- 임베딩 인덱스가 `indexing` 인 동안 팔레트 "본문·뜻" 구역은 키워드 결과만 — 준비되면 자동 재검색하지만
  그 순간 행이 늘어나는 것이 사용자에게 어떻게 보이는지는 미검증.
