## Context

AI 점검이 같은 개념을 다루는 두 페이지(`duplicate`)를 짚고, 사람이 합치기 제안을 받아 한 페이지로 만드는 기능을 더했다.
위키화처럼 작업 브랜치·승인 화면을 거칠지, AI로 고치기처럼 제안을 받는 것을 승인으로 볼지가 첫 갈림길이었다. 슬라이스
리뷰(파인더·오류 처리·화면)가 링크 고치기·반쯤 바뀐 상태·같은 파일·창 닫기를 짚었고 아래는 거기서 굳힌 결정이다.

## Decisions

- **제안을 받는 것이 승인이다.** 승인 화면은 실행 기록·분량 장부가 필요하고 지우기를 거절할 수 없어(`review-service` 가 D 를
  `others` 로 둔다) 합치기에 맞지 않는다. 받으면 `edit: merge <지울> into <남길>` 커밋 하나, 바로 되돌리면
  `undo: merge <지울>` 커밋 하나다.
- **남길 페이지는 앱이 고른다.** 더 많이 가리켜지는 쪽(고칠 링크가 적다), 같으면 글이 긴 쪽, 그것도 같으면 경로순. 창이
  두 페이지 이름을 받기 전에 보인다. 바꾸는 손잡이는 두지 않았다.
- **합친 글은 엔진 제안 본문 + 남길 페이지의 속성.** 옛 제목과 옛 별칭은 `aliases` 에 더한다(`setProperty` — 다른 줄의
  주석·키 순서 유지). 못 더하면 합치지 않는다 — 옛 이름의 링크·검색이 끊긴다.
- **링크는 지울 페이지로 풀리는 것만 고친다.** `#제목`·`|별칭`·`![[…]]`·표 안의 `\|` 는 그대로, 코드 블록(같은 문자로 같거나
  긴 표식이 닫는다)·인라인 코드·URL 안은 건드리지 않는다. 남길 페이지 이름은 basename 이 하나뿐이면 basename, 겹치면 경로형.
- **반쯤 바뀐 상태를 남기지 않는다.** 남길·지울 페이지와 링크를 고칠 문서에 기록되지 않은 변경이 있으면 쓰기 전에 거절한다.
  쓰기·커밋 도중 실패하면 손댄 파일을 맨 위 커밋 상태로 돌리고, 돌리지 못한 파일은 오류에 이름을 붙인다. 되돌리기도 같다.
- **되돌리기는 합친 커밋이 맨 위일 때만.** 그 뒤 다른 커밋이 있으면 거꾸로 적용이 엉킬 수 있어 거절한다.
- **같은 파일을 두 번 집지 않는다.** 대소문자만 다른 두 경로는 macOS·Windows 기본 디스크에서 한 파일이다 — 그대로 합치면
  남길 글을 쓰고 같은 파일을 지운다. 실제 경로로 견줘 거절하고, AI 점검도 그런 짝을 버린다.
- **합치는 중에는 창을 닫지 않는다.** 닫아도 합치기는 끝까지 가는데 결과와 되돌리기가 사라진다. 합친 직후 초점은
  "합친 페이지 열기" 에 둔다 — Enter 한 번에 되돌려지지 않게.

## Rejected

- **위키화 작업 브랜치 → 승인 화면** — 위 이유.
- **`git revert` 를 그대로 커밋** — 제목이 `Revert "…"` 라 앱의 `undo:` 규칙과 어긋난다. `--no-commit` 뒤 앱 이름으로 커밋한다.
- **엔진이 속성 블록까지 쓰게 하기** — 남길 페이지의 속성이 바뀐다. 엔진이 붙여도 떼어 낸다.

## Open

- 제안 만들기를 바꿔 잡는 길(창을 닫았다 다시 연 때)에 단위 테스트가 없다 — 정적 추론만. 앞의 엔진이 아직 끝나지 않았으면
  새 제안이 "AI 점검이 진행 중이에요" 를 받을 수 있다.
- 합치기는 main 스레드의 동기 git·파일 읽기다(보관함 전체 문서를 한 번 읽는다). 편집 저장과 같은 방식이고 시간은 재지 않았다.
