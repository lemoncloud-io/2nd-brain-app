## Context

비개발자가 앱 하나로 첫 위키를 승인하기까지 걸음이 끊겨 있었다. 시작하기는 연결→보관함 두 단계였고, 보관함은 폴더를 골라
번들 뼈대로 만들었다. GitHub 연결은 설정 깊숙이 있었고, 개인 저장소도 승인하면 팀 확인 요청(PR)을 열어 사람이 웹에서
직접 합쳐야 첫 성공이 끝났다. 이 결정은 첫 실행 흐름을 다시 짜면서 사용자와 함께 정한 것이다.

## Decisions

- **첫 성공은 위키화 → 승인 → GitHub 에 올라감까지다.** 첫 위키를 보는 데서 멈추지 않는다.
- **순서는 질문 → AI 연결 → GitHub 로그인 → 보관함 → (자료 → 위키화 → 승인)** 이다. 질문을 먼저 해서 무엇을 하려는지부터 듣는다.
  답은 보관함이 생기기 전까지 설정에 두고, 보관함이 생기면 `purpose.md` 로 옮겨 커밋한다.
- **보관함 원본은 GitHub 템플릿 저장소의 generate + clone 이다.** 템플릿은 lemoncloud-io 의 새 비공개 복제이고, 내용은 그대로 둔다.
  버전은 고정하지 않고 최신을 받는다. 받은 뒤 `REQUIRED_ENTRIES` 를 검사하고, 빠졌으면 폴더를 지우고 이유를 알린다.
- **GitHub 은 필수 단계다.** 다만 "나중에 하기"와 계정 만들기 링크를 둔다. 나중에 하면 번들 뼈대(`createVault`)로 만든다.
  템플릿이 비공개라 받을 수 없는 동안에도 이 길로 만든다.
- **저장소 이름과 위치는 자동으로 정한다.** 저장소는 내 계정의 비공개 `2nd-brain`(중복이면 `-2`…)이고, 폴더는 문서 폴더의
  `2nd-brain`(-2)이다. 폴더는 "자세히" 에서만 고른다.
- **엔진은 로그인된 쪽을 자동으로 고른다.** 둘 다 아니면 Claude 를 쓰고 "Codex 쓰기"를 보인다.
- **온보딩에서 템플릿 3개 고르기는 뺀다.** 질문의 답이 그 자리를 대신해 `purpose.md` 에 들어간다.
- **위키화는 자동으로 시작하지 않는다.** 버튼 한 번에 시작하고, 몇 분 걸리고 구독 사용량이 든다고 함께 안내한다.
- **자동으로 올리는 범위는 개인 보관함 전부다.** 첫 승인만이 아니라 늘 올린다. 팀원 보관함의 확인 요청 흐름은 그대로 둔다.
- **개인인지는 승인할 때마다 collaborators API 로 판별한다.** 주인이 로그인 아이디이고 구성원이 나뿐이어야 개인으로 본다.
  확인에 실패하면 확인 요청 경로로 간다(안전한 쪽). 로컬 표시로 대신하지 않는다 — 초대 직후의 낡은 "혼자" 판정으로 남의
  기본 줄기에 바로 올리는 일이 생긴다.
- **기존 사용자에게는 "GitHub에 올리기" 걸음 하나만 더한다.** 전체 흐름으로 끌고 오지 않는다. 준비 완료 조건(연결 + 보관함)은 그대로다.
- **중간에 끝내도 상태에서 다시 계산한다.** 따로 저장하는 것은 질문의 답 하나다.

## Rejected

- **번들 뼈대·빈 뼈대를 첫 보관함 원본으로 삼기** — 첫 화면에 보여 줄 위키가 없다. 뼈대는 "나중에 하기"의 길로만 남긴다.
- **템플릿 sha 고정** — 이번에는 최신을 받고 필수 항목만 검사한다. 템플릿 저장소에 `.claude/` 설정이 실려 오면 엔진이 그것을 읽으므로,
  템플릿 저장소가 생기면 sha 고정 비교를 후속으로 다시 본다.
- **첫 승인만 자동으로 올리기** — 두 번째 승인부터 다시 PR 을 열면 혼자 쓰는 사람은 웹에서 매번 합쳐야 한다.

## Open

- 템플릿 저장소 `lemoncloud-io/2nd-brain-template` 은 아직 없다. 없으면 앱은 404 를 받고, 앱 뼈대로 만든 뒤 내 저장소에 올리는 길로 간다.
- 저장된 GitHub 아이디가 지금 토큰의 주인인지는 확인하지 않는다(후속).
