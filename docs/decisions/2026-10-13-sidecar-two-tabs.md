## Context

오른쪽 채팅 칸에 탭이 다섯(채팅 · 참고한 페이지 · 위키 초안 · 웹 조사 · 기록) 있었다. 제품 오너 확인(2026-10-13):
"기능이 너무 많다. 웹 조사는 필요 없을 듯. 최대한 단순하게." 같은 날 UX 리뷰(`.impeccable/backlog.md` 2026-10-13 런)는
채팅을 뺀 네 탭이 다른 화면이 채워 주기 전에는 비어 있고, 웹 조사 하나가 탭 하나와 진입점 여섯 곳(채팅 답 아래 단추 ·
`/조사` · 검색 결과 없음 · 점검의 빠진 페이지 · 승인 검토 항목 · 탭 안 입력칸)을 차지한다고 적었다.

## Decisions

- **웹 조사(Deep Research)를 없앤다.** 탭, 진입점 여섯 곳, main 의 조사 대기열과 IPC 채널, 엔진의 `research` 프로필
  (`WebSearch`·`WebFetch` 허용)을 같이 지운다. 대신하는 기능은 두지 않는다.
- **앱이 직접 웹 도구를 열지 않는다.** 어느 엔진 프로필에도 `WebSearch`·`WebFetch` 가 없다 — **2026-10-14 에 채팅에 한해 뒤집었다**
  (`2026-10-14-chat-engine-web-tools.md`). 웹 조사 탭·대기열은 돌아오지 않는다. 바깥 자료는 자료 넣기
  (파일 · URL)로 들어온다. 사용자가 설정에서 켠 MCP 서버는 별개다 — 채팅·노트 쓰기 엔진에만 넘어간다.
- **무거운 작업 슬롯은 AI 점검 하나만 쓴다.** 조사와 점검이 한 칸을 나눠 쓰던 규칙은 "점검은 한 번에 하나" 로 줄었다.
- **`/조사` 는 명령 목록에서 빠진다.** 치면 모르는 이름의 기존 동작대로 그냥 질문으로 간다.
- **이미 쌓인 조사 대기열 파일은 건드리지 않는다.** userData 에 남지만 읽는 코드가 없다. 지우는 코드를 넣지 않는다.

## Consequences

- 검색 결과가 없을 때의 다음 걸음은 "채팅으로 물어보기" 하나다.
- 점검의 빠진 페이지 항목과 승인 검토 항목에서 조사로 넘어가는 단추가 없다.
- 채팅에 웹 검색을 붙이려면 쓰기 권한 경계와 사용량 확인을 새로 설계해야 한다 — 이 결정의 범위 밖이다.
