## Context

리더 "…" → 기록 을 더했다. 옆 칸에 그 문서의 버전(누가 · 언제), 가운데에 고른 버전과 지금 글의 다른 줄,
"이 버전으로 되돌리기". 볼트의 모든 변경이 커밋이라 기록은 git 로그에서 읽는다. 슬라이스 리뷰(파인더·오류 처리·화면)가
누가 판정, 되돌리기 안전, 실패 표시를 짚었고 아래는 거기서 굳힌 결정이다.

## Decisions

- **누가는 커밋에서 가른다.** AI가 씀 = `merge: app/ingest-*` 머지가 들여온 커밋, 승인 대기 중인 작업 브랜치의 커밋,
  제목이 `note:`(채팅이 쓴 노트)·`feat:`(위키화 에이전트 결과 커밋, vault-ingest-agent.md) 인 커밋. 에이전트 커밋은
  사용자 전역 git 이름으로 남아 작성자로는 못 가른다. 내가 고침 = 로그인한 내 GitHub noreply 주소. 로그인하지 않았으면
  앱 이름 커밋을 "고침"(이름 없이)으로 둔다 — 로그인 전 팀원 커밋까지 "내가" 로 단정하지 않는다.
- **되돌리기는 새 길을 만들지 않는다.** 그 버전 글을 `writeWikiPage` 로 저장한다 — `edit:` 커밋 하나, 해시 확인,
  작업 브랜치 거절이 편집 저장과 같다. main 에 되돌리기 채널이 없다.
- **비교·되돌리기 기준은 버전을 고른 때의 글이다.** 보는 사이 문서가 바뀌면(받기·AI 가 씀) 비교가 저절로 바뀌지 않고
  되돌리기를 막은 채 "다시 견주기" 를 권한다. 플랜의 "목록을 받은 뒤 바뀌면 거절" 보다 좁지만 같은 것을 막는다.
- **버전 글은 기록에 있는 커밋만 읽는다.** `rev` 는 40자 sha 이고 이 문서의 `--follow` 기록에 있어야 하며, 경로는
  화면이 아니라 기록에서 찾는다(이름이 바뀌기 전 버전은 옛 이름).
- **위키화 머지가 들여온 커밋은 머지 sha 로 기억한다.** 머지가 들여온 것은 바뀌지 않아 저장마다 다시 걷지 않는다.
- **실패를 빈 목록으로 보이지 않는다.** 기록을 남기지 않는 문서(git 이 무시하는 파일·기록 없는 보관함)는 "저장하면 쌓여요"
  대신 그렇다고 말한다. 누가 판정이 실패하면 목록은 주고 일부 이름이 정확하지 않을 수 있다고 알린다. 200개를 넘으면
  줄였다고 알린다. 읽기 실패 원문은 "자세히" 로 접는다.
- **슬라이스는 PR #48(GitHub 로그인 하나) 위에 쌓는다.** 커밋 작성자 = GitHub 아이디가 그 PR 에만 있다.

## Rejected

- **목록을 받은 때의 해시로 되돌리기 확인** — 목록은 저장마다 다시 받아 기준이 계속 바뀐다. 사람이 본 비교와 묶이지 않는다.
- **비교를 지금 글에 맞춰 저절로 갱신** — 사람이 본 것과 되돌릴 것이 조용히 달라진다(슬라이스 리뷰 Important).
- **main 의 git 호출을 비동기로** — 편집 저장(`WikiService.write`)이 같은 동기 git 을 쓴다. 비용은 재지 않았다.
- **"…" 메뉴 대신 기록 단추 하나** — 플랜(그릴링 합의)이 리더 "…" 메뉴를 정했다.

## Open

- 기록 칸이 열려 있으면 리더와 같은 문서를 한 번 더 읽는다(해시를 얻으려고). 비용은 재지 않았다.
- 비교를 닫을 때 키보드 초점이 고른 버전으로 돌아가지 않는다.
