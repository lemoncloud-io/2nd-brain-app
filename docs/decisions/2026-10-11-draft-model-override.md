## Context

위키화 속도 A/B(knowledge 248쪽 복제본, Sonnet 실호출): 관련 컨텍스트 8전문→3×2k자 캡으로
프롬프트는 1/6(33,172→5,147자)이 됐으나 단건 체감은 -5초 안팎에 그쳤다. 3만자대에서는 CLI 기동과
모델 지연이 지배적이다. 5건 묶음에서는 -40%(58.8→35.4초)가 났다. 단건 위주가 pain이면 다음 카드는
초안 모델 분리다.

## Decisions

- **모델 하나 원칙은 유지하고, 위키 초안만 예외 하나로 둔다.** `EngineSettings.draftModel` —
  없으면 위 모델과 같다. 초안 호출(`draft` 프로필, 읽기 전용 1회)에만 쓴다. 채팅·위키화 본체·점검·조사는
  그대로 위 모델을 쓴다.
- **입력은 고급에만 둔다.** 10-01 결정(개발자 손잡이는 고급 접기)을 그대로 따른다. 비우면 같은 모델이 된다.
  초안 모델을 쓰고 있으면 고급은 펼친 채로 열린다.
- **다른 칸의 저장이 초안 모델을 지우지 않는다.** AI 설정 목록·모델 직접 입력 저장 시 기존 draftModel 을
  함께 보낸다. 비어 저장하면 기본 모델로 돌아가는 기존 규칙과 같다.
- **엔진을 바꾸면 초안 모델도 비운다.** Claude 별칭을 Codex 가 모른다는 기존 이유와 같다.

## Rejected

- **용도별 모델 칸 부활** — 10-01 에서 뒤집은 결정을 되돌리지 않는다. 예외는 숨은 칸 하나다.
- **초안 모델을 조용히 낮추기(기본 haiku)** — 사람이 고르지 않은 모델로 바꾸지 않는다. 품질 게이트가 승인이라
  안전해도, 과금 주체가 사용자 구독이므로 기본값은 손대지 않는다.

## Open

- Codex 엔진의 초안 모델 이름은 사용자가 직접 넣는다. 목록이 없어 검증 불가.

## Measured (2026-10-11, 같은 PR)

동일 단건 클리핑(본문 2.5k자, 프롬프트 7,064자) × knowledge 248쪽 복제본 × 실호출:

| 초안 모델 | TTFT | 총 | 결과물 |
|---|---|---|---|
| sonnet | 22.0초 | 22.7초 | 본문 1 + 토픽 4 |
| haiku | 23.8초 | 24.4초 | 본문 1 (토픽 없음) |

Haiku 가 빠르지 않았다. 이 입력 크기에서는 첫 글자 지연이 지배적이라 모델 출력 속도 차이가
묻힌다. 게다가 Haiku 초안은 엷었다(토픽 페이지 없음). 빠른 초안 모델은 기본값으로 두지 않는다 —
고급의 선택지로만 남긴다. 단건 속도의 다음 카드는 재시도·호출 구조 쪽에 있다.
