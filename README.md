# 2nd-brain

[English](README.en.md)

<img src="docs/brand/lockups/2nd-brain-horizontal-light.svg" alt="2nd-brain" height="64">

비개발자가 앱 하나로 Claude(또는 Codex) 연결 → 개인 볼트 생성 → 클리핑 → 위키화 → 페이지 승인까지
끝내는 데스크톱 앱 (macOS arm64·Windows x64 대상).

## 기능

- **시작하기** — 첫 실행은 질문("무엇을 정리하고 싶으세요?" — 답은 보관함의 `purpose.md` 에 커밋)→AI 연결(설치 버튼·브라우저
  로그인, 끝나면 자동으로 넘어감)→GitHub 로그인(계정 만들기 링크·"나중에 하기")→보관함→GitHub에 올리기 다섯 단계이고, 머리에
  "5단계 중 N단계" 를 보인다. 보관함은 폴더를 고르지 않고 버튼 한 번으로 문서 폴더 아래 `2nd-brain`(있으면 `-2`…)에 만든다 —
  로그인했으면 템플릿 저장소(`SECOND_BRAIN_VAULT_TEMPLATE`, 기본 `lemoncloud-io/2nd-brain-template`)로 내 계정에 비공개
  `2nd-brain` 저장소를 만들어 받고(볼 수 없는 템플릿이면 앱 뼈대로 만들어 내 비공개 저장소에 올린다), 나중에 하기면 이 컴퓨터에만
  만든다. 원격 없는 보관함은 마지막 걸음 "GitHub에 올리기" 가 펼쳐져 남는다(준비 조건은 아니다). 시작하기를 한 번 끝낸 사람은
  AI 연결→보관함→GitHub에 올리기만 본다. 시작하기 맨 위에서 화면 언어(한국어/English)를 고를 수 있다. 연결과 보관함이면 준비가 끝나고 다음 실행부터 오늘 노트로 열린다. Claude·Codex 는 앱이 벤더 설치 스크립트를 직접 돌려 깐다 —
  터미널을 열지 않고 다른 선행 설치도 없다. 버튼이 실패하면 사유와 함께 OS 별 한 줄 직접 설치 안내·증상별
  대처가 펼쳐진다. 앱이 깐 CLI 는 `userData/installed-cli` 에 표시해 두고, 언인스톨러는 표시된 것만 지운다
- **오늘** — 앱을 열면 `private/` 의 오늘 노트가 뜬다. 노트 위 띠가 지난 노트 미결(`10/10 노트에 남은 일 2`)과 오늘 할 일 n/m 을 말하고,
  `오늘 정리하기` 는 보낼 문장을 채팅 입력칸에 채워 준다(쓰던 글이 있으면 뒤에 덧붙이고 띠에 알린다) — 읽어 보고 Enter 로 보낸다.
  지난 노트로 건너가도 띠가 남아 `← 오늘 노트로` 로 돌아온다.
  노트가 아직 없으면 띠는 뜨지 않는다. 만들기는 채팅에 시킨다("오늘 노트 만들어줘" — 빈 탭의 `오늘 노트 만들기` 가 그 문장을 채운다)
- **GitHub 팀 저장소** — GitHub 로그인 하나(앱이 보여 주는 여덟 글자를 브라우저에 넣고 승인)로 올리기·받기·팀 보관함에
  들어가기·팀 확인 요청을 모두 한다. 토큰은 OS 키체인으로 암호화해 두고 git 에는 환경 변수로만 넘긴다(github.com 으로
  가는 요청에만). 로그인 전에는 연결·받기가 로그인부터 하라고 하고, 예전 브라우저 로그인으로 연결해 둔 보관함은 사이드바
  받기 줄이 "GitHub 다시 연결이 필요해요" 로 안내한다. 저장소는 github.com 것만 받는다. 앱이 만드는 커밋(편집·받기 저장·되돌리기)의
  작성자는 로그인한 GitHub 아이디다(로그인 전에는 `2nd-brain`).
  - 대표: 팀 저장소를 앱에서 만든다 — 내 계정이나 내가 속한 조직 아래 비공개 저장소를 만들고 연결해 첫 올리기까지 하고
    (혼자 쓰면 팀원 없는 팀 저장소), GitHub 아이디로 팀원을 초대한다. 이미 만든 빈 저장소 주소로 연결할 수도 있다.
  - 팀원: 시작하기의 "팀 보관함에 들어가기" 에서 로그인하면 들어갈 수 있는 보관함(`VAULT_RULES.md` 가 있는 저장소, 최근 30개)과
    받은 초대가 보인다. 골라 누르면(초대면 수락하고) 받아 바로 연다. 목록에 없으면 주소로 받는다.
  - 혼자 쓰는 내 저장소(주인이 로그인 아이디이고 구성원이 나뿐, 열린 확인 요청 없음)는 승인하면 확인 요청 없이 기본 브랜치를
    바로 올린다(팀 변경 받기 → 공개 검사 → 올리기). 결과 카드에 "GitHub에 올렸어요 · GitHub에서 보기", 올린 넣기는 되돌리지 않는다.
    못 올리면 사유와 "다시 올리기". 구성원이 있거나 조직 저장소이거나 확인하지 못하면 팀 확인 요청(PR)을 연다.
  - 올리는 것은 승인된 기본 브랜치뿐이다. 올라가는 것은 위키와 넣어 둔 원본 자료다 — 저장소가 공개면 **올리지 않고**
    사유를 말하고(빈 저장소가 아닐 때도 같다), 연결 해제·다른 저장소로 바꾸기도 설정에 있다
- **자료 보관함** — 새 보관함 생성(뼈대 + git, 리서치·독서·업무 템플릿)·열기, 볼트 전환 시 진행 중 작업 취소
- **클리핑** — 글(.md·.txt)과 URL 을 `Clippings/` 로. PDF·한글(.hwpx·.hwp)·엑셀(.xlsx)·워드(.docx)·파워포인트(.pptx) 는 글자와 표를 뽑아 .md 로 넣는다(워드는 제목·목록, 파워포인트는 슬라이드마다 한 절, 그림은 자리만 남기고 워드·파워포인트는 문서에 적힌 대체 텍스트를 자리표에 같이 남김. 옛 .xls·.doc·.ppt 는 저장 안내). 파일은 여러 파일 한 번에·파일 고르기, 위키화 입력함
- **위키화·승인** — 옆 칸 위키 초안 탭이 기다리는 자료를 이름으로 보여 주고(누르면 읽는다), Claude 가 볼트를 위키로, 확정 전 병합·원복 수 확인 후 기본 브랜치 반영, 거절 페이지는 원복, 병합 직후 되돌리기(전체 승인·전체 거절은 목록 위 줄). 승인은 `읽기` 로 열어 본 페이지 수("읽어 본 N개 / 전체 M개")를 목록 위와 확인 바에 보이고, 넣은 뒤 결과 카드에서 `위키에서 보기` 로 첫 페이지를 연다. 위키화 기록은 단계 줄과 진행 수만 보이고 AI 초안 본문은 접힌 자세히에 둔다. 위키화를 취소하거나 AI 가 초안을 하나도 못 쓰면 자료는 위키화 대기함으로 돌아와 바로 다시 위키화할 수 있다(위키화 도중 앱이 꺼졌으면 다음 위키화가 시작하며 되돌린다). 페이지가 만들어진 뒤의 실패는 승인에 남는다
- **Wiki** — 트리·리더(GFM·wikilink·frontmatter, 누르면 저장되는 체크박스·절별 `n/m` 목차, 링크에 마우스를 잠시 올리거나 Tab 으로 가면 그 페이지 앞부분이 곁에 뜨는 미리보기 — 근거 칸·분할 칸도 같다), 한 칸에서 읽으며 쓰는 라이브 미리보기 편집기(커서 없는 줄은 기호를 숨긴다 · 맨 위 속성은 `속성 N개 · 펼치기` 한 줄로 접힌다 · "꾸밈 기호 보기" 토글 · ⌘/Ctrl+클릭으로 링크 이동 · `[[` 자동완성 · 아래 줄에 글자·단어 수 — 공백 넣어 센 글자, 띄어 쓴 단어, 속성·꾸밈 기호·링크 주소 빼고, 고른 글이 있으면 그 분량), 그림 붙여넣기·끌어 놓기 → `attachments/` + `![[…]]`(글과 한 `edit:` 커밋), 리더의 속성 칸(값을 눌러 고치기·더하기·지우기 — 목록 키는 쉼표, 주석·순서 보존), 편집기의 "템플릿"(`templates/*.md` 를 커서 자리에, `{{title}}`·`{{date}}`·`{{time}}` 채움, 템플릿 속성은 없는 키만 합침), 편집기의 "AI로 고치기"(고른 글과 지시를 보내 고친 글 제안을 지금 글 옆에 보이고 "바꾸기"·"그대로 두기" — 바꾼 것도 ⌘Z 로 빠지고 저장해야 `edit:` 커밋). 편집은 리더에서 읽던 자리에서 열리고, 저장·취소하면 리더가 그 자리로 돌아오고 "저장했어요" 한 줄이 잠깐 뜬다. 편집하는 사이 문서가 바뀌면(팀 변경 받기·다른 앱) 저장을 막고 알린다 — "내 글 복사" 로 입력을 챙기고 "내 글 버리고 다시 불러오기". 같은 문서를 둘이 고친 것을 고르기 전에는 저장하지 않는다
- **Search** — 키워드(BM25·제목 가중·한글 부분 일치) 검색, 스니펫 강조,
  md 아닌 파일(PDF·그림 등)은 이름·경로로 찾고(`.pdf`·`보고서 pdf`) 종류 단추(전체·문서·PDF·그림·HTML·그 밖)로 거른다 — ⌘K 도 같다,
  글자 일치가 없으면 채팅으로 물어보기
- **Graph** — wikilink 그래프를 돌려 보는 입체(3D)로 그린다. 페이지는 구 모양에 늘 같은 자리로 놓인다 — 종류와 위키 안
  폴더마다 경도 한 구간을 받아 큰 폴더는 빽빽한 띠로, 작은 폴더는 반대편에 흩어져 보이고, 가운데 오브와 궤도 링이 떠 있다.
  이어진 수가 많은 페이지일수록 크고 진하게(다크 테마에서는 밝게 빛나게) 보인다. 평소에는 가까운 페이지 사이 선과 일부 표본
  선만 긋고, 점을 짚으면 그 점의 선을 전부 보이며 이웃만 남긴다. 점을 누르면 카메라가 그 점 앞으로 날아가 고른 채로 두고
  (선은 그 점의 색으로 진하게, 이웃 이름표, 선을 따라 흐르는 점) 옆 칸에서 그 페이지를 열고 본문 뒤에 접힌 "이어진 페이지" 목록을 둔다 —
  목록을 누르면 그래프도 그 점으로 옮겨 가고, 빈 곳을 누르면 고르기가 풀린다. 종류·묶음으로 골라 볼 수 있다. "성장 재생" 버튼은 지금 보이는 페이지들이 실제 링크를 따라 한 점에서 전체로 자라는 15초 연출을 보여 주고,
  끝나면(또는 다시 누르면) 같은 구 모양 그림에 머문다. 재생 중에도 돌리기·확대·점 열기가 된다
- **Lint** — 구조 점검(vault_verify — 속성 블록 형식, `next_action` 한 줄에 할 일 하나 등) + AI 점검(모순·오래됨·누락 페이지·제안·같은 내용, 진행 중 읽은 페이지 수·경과 시간),
  같은 내용 두 페이지는 "두 페이지 합치기" — AI가 합친 글을 두 원문 옆에 보이고, 링크를 고칠
  문서·지울 페이지를 알린 뒤 받으면 `edit: merge …` 커밋 하나(합친 글, 옛 제목은 `aliases`, 다른 문서의 `[[옛]]` 링크 —
  코드·URL 안은 그대로 — 고침, 옛 파일 삭제). 바로 "되돌리기" 하면 `undo: merge …` 커밋 하나로 전부 돌아오고, 그 뒤 다른
  변경이 생겼으면 되돌리기를 막는다
- **Chat(하루의 일을 시키는 곳)** — 오른쪽 칸에 늘 열려 있고 어디서든 ⌘J. 빈 대화는 시키는 말을
  예시로 준다("오늘 노트 만들어줘"·"어제 미결만 모아줘"·"이 계획을 체크리스트로 바꿔줘").
  질문은 Claude Code 데스크탑처럼 그대로 보낸다 — 앱이 문서를 골라 앞에 붙이지 않고, 보관함을 어떻게 찾을지는 AI가
  보관함의 `CLAUDE.md` 와 읽기 도구로 정한다. 앱 규칙(쓸 수 있는 곳·앱에서 여는 경로·오늘 노트)은 시스템 프롬프트
  로 세션을 열 때 한 번 싣고, 이번 질문이 기본과 다를 때(읽기만 할 때·승인 대기)만
  질문 앞에 한 줄 붙인다. 대화마다 AI 프로그램을 하나 켜 두고 질문을 그 안의 다음 턴으로 보낸다 — 질문마다 새로 띄우지 않아
  앞 대화를 그대로 기억하고, 사용자 설정의 훅·경고가 질문마다 다시 돌지 않는다. Claude 는 Agent SDK 로 이 컴퓨터의 claude 를,
  Codex 는 `codex app-server` 를 띄운다(app-server 가 없는 옛 Codex 는 업데이트하라고 안내한다). 켜 둔 대화는 셋까지, 10분
  쉬면 끄고, 앱을 다시 켜거나 끈 대화로 돌아오면 앞 대화를 이어 붙여 다시 연다 — AI 쪽에서 앞 대화가 사라졌으면 알리고 새로 시작한다. 답 아래 참조 칩은 AI가 직접 읽었거나 답이 경로로 인용한 붙인 문서만이다 — 답이 끝난 뒤 붙는다.
  스트리밍 답(GFM·KaTeX 수식·Mermaid 다이어그램, 언어 머리줄·복사 단추가 붙은 코드 블록, 쓰는 동안 펴 두고 끝나면 접는
  생각 블록, 첫 글자 전 점 셋)·참조 칩·대화 목록. 답 본문에 코드 글자로 적힌 보관함 파일 경로는
  (그 파일이 보관함에 있을 때) 눌러서 가운데에 연다 — md 는 리더, html 등은 미리보기. 채팅 지시문은 파일을 터미널 명령으로 여는 법을 안내하지 말라고 한다. 위를 읽는 동안은 따라 내려가지 않고 "맨 아래로" 단추가 새 답을 알린다.
  답마다 복사·답 남기기(마지막 답만 늘 보이고 지난 답은 올려 둘 때), 내 질문은 복사·고쳐서 다시 묻기(입력칸에 올린다).
  마지막 답에는 다시 답하기 — 그 답을 지우고 같은 질문에 새로 답한다(대화에는 질문 하나와 새 답만 남는다. 답이 만든 파일이
  남아 있으면 카드에서 되돌린 뒤에 된다). 실패한 질문의 다시 묻기도 질문을 한 번 더 붙이지 않는다.
  답하는 중에도 다음 질문을 써 둘 수 있다 — 보내기만 막힌다. 노트와 계획은
  말로 시키면 파일로 쓰고 답 아래 카드에서 열기·되돌리기가 된다. 카드의 "검토" 는 고친 파일을 고친 곳으로 나눠
  지운 줄·더한 줄을 보이고, 곳마다 "두기"(그대로)·"되돌리기"(그 곳만 답 전으로, `undo:` 커밋)를 누른다 — 답 뒤에 사람이 고친 파일은 나누지 않는다. 파일을 끌어다 놓으면 자료로 들어가고(주소만 붙여 넣으면 "자료로 넣기" 를 권한다),
  "정리해줘"·"이상한 데 없어?" 같은 말에는 답 아래에 위키화·점검·승인 버튼이 붙는다. 답은 물은 말과
  같은 언어로 온다. "답 남기기" 는 답을 `outputs/` 의 질의 답 노트(`query-output`)로 남긴다 — 위키화 입력함이 아니다.
  문서는 `@` 로 붙인다 — `@` 를 치면 보고 있는 문서가 맨 위, 이어서 최근 문서가 뜨고 제목·경로로 좁혀 고른다. 보고 있는 문서는
  저절로 붙지 않고 입력칸 위 `@ <제목>` 단추 한 번으로 붙는다(8개까지, 문서마다·전체 분량 상한을 넘으면 앞부분만). 질문에 GitHub PR·이슈 주소
  (`https://github.com/<owner>/<repo>/pull/<번호>`·`…/issues/<번호>`)를 넣으면 앱이 GitHub 로그인으로 그 PR 의 제목·상태·본문·변경 파일 목록(첫 100개),
  이슈의 제목·상태·본문을 읽어 질문과 함께 보낸다(한 질문에 3개까지, 주소마다 분량 상한을 넘으면 본문 앞부분만) — 다시 답하기도 다시 읽는다. 바뀐 줄·댓글은 읽지 않는다.
  그 밖의 웹 주소(`http(s)://…`)는 로그인 없이 보이는 페이지의 제목과 본문을 읽는다(한 질문에 3개까지, 주소마다 8초·1MB — 이 컴퓨터·사내망 안쪽 주소,
  PDF·그림, 로그인해야 보이는 페이지는 읽지 않는다).
  못 읽으면(로그인 전·볼 수 없는 저장소·연결 끊김·글이 아닌 주소) 입력칸 위에 이유와 할 일을 한 줄로 알리고 답은 그대로 낸다. 채팅 엔진에는 웹 조회·검색 도구가 열려 있어
  (Claude `WebFetch`·`WebSearch`, Codex `web_search="live"`) 질문에 주소를 쓰지 않아도 엔진이 스스로 찾아 읽는다 — 묻는 화면 없이 돈다. 노트 쓰기 Claude 채팅은 셸·서브에이전트·사용자 설정의 MCP·스킬까지 쓰고, 허용 범위 밖 도구는 채팅 칸의 승인 카드(허용·이 대화에서 계속 허용·거절)로 묻는다 — 답을 기다리는 동안 실행이 시간 초과로 죽지 않고, 노트 범위 밖 쓰기는 승인했어도 되돌린다. 묻는 정도는 설정 채팅 칸에서 정한다 — 물어보기(기본)·파일 고치기는 바로·전부 바로(묻지 않고 실행, 주의). 답이 오는 동안 쓰는 도구를 한 줄로 보인다(Codex 는 승인 왕복 없이 예전대로 sandbox 안에서 명령을 돌린다). 위키화·AI 점검·위키 초안·선택 영역 고치기에는 웹 도구가 없다. 대화 압축은 Claude 에서는 웹 도구 없이, Codex 에서는 읽기 전용 sandbox 로만 돈다(웹 검색은 대화 단위 설정이라 그 턴만 끄지 못한다). `/` 를 치면 사용자의 Claude 스킬 목록 —
  `~/.claude/skills`·보관함 `.claude/skills`·플러그인 스킬을 CLI 가 시작할 때 알려 주는 대로 보이고(사용자·보관함 스킬은 `SKILL.md` 설명을 붙인다),
  고르면 입력칸이 `/<이름> ` 이 되어 뒤에 덧붙여 보낸다. 질문은 그대로 CLI 에 가서 데스크탑처럼 스킬이 돈다. 목록은 채팅 칸이 뜰 때
  Claude 세션을 하나 미리 열어 받고(모델을 부르지 않는다) 새 대화의 첫 질문이 그 세션을 이어받는다. 보관함마다 기억해 두며 `/` 를 칠 때마다 뒤에서 새로 받는다. Codex 는 스킬이 없어 목록이 뜨지 않는다. 위키 초안·점검·압축·새 대화는 각자의 탭·단추에 있다.
  화면 캡처·복사한 그림은 입력칸에 붙여 넣으면 질문에 붙는다(한 질문에 5장, 긴 변 1568px 로 줄여 보낸다). 입력칸에 작게 보이고 × 로 빼며, 누르면 크게 본다(질문 말풍선의 그림도).
  보낸 질문 말풍선에도 보인다 — 그림은 대화 기록에 남기지 않아 다시 연 대화에는 그림 수만 보인다. Claude 는 메시지 블록으로, Codex 는 임시 파일(`localImage`)로 받는다
- **승인 검토 항목** — AI 점검 발견·넣기 전 검사 결함을 모아 열기·나중에(접힌 칸에서 다시 보기). 빠진 페이지 항목은 그 페이지가 생기면(위키화·링크 칸의 만들기 어디서든) 저절로 빠진다
- **엔진** — Claude Code CLI 또는 Codex CLI 선택(둘 다 앱 안에서 로그인·연결 끊기), 모델 하나(채팅·위키화·AI 점검이 같이 쓴다 — 엔진을 바꾸면 기본 모델로 돌아간다).
  위키 초안만 고급의 "위키 초안 모델"로 따로 둘 수 있다(비우면 위 모델과 같음).

  다시 시작을 한 번 더 누른다. 레포가 공개되기 전까지 자동 업데이트는 꺼져 있고 "새 버전은 팀이 전해 준다" 로 보인다 —

- **자료 보관함** — 설정에서 언제든 다른 보관함을 열 수 있다. 뼈대가 없는 Obsidian 폴더를
  고르면 읽기 중심으로 열린다 — 트리·리더로 읽을 수 있고, 위키 초안 만들기·점검·팀 동기화는 쓸 수 없다고

  있던 파일은 한 글자도 바꾸거나 옮기지 않고 규칙 파일·wiki·raw·대기함 중
  없는 것만 더하며(이름이 같은 파일은 그 사람 것을 둔다, `.gitignore` 는 빠진 줄만 덧붙인다), 노트 사본을 위키화 대기함에
  넣는다. git 이 없으면 새로 시작하고, 있으면 그 기록 위에 앱이 더한 것만 커밋한다. 그다음은 "위키화하러 가기" → 승인이다.
  위키화를 도중에 멈추거나 다른 도구가 만든
  브랜치에 남아 보관함이 평소 상태를 벗어나면 "보관함 상태 되돌리기" 로 터미널 없이 되돌린다. 앱에서 고친
  문서는 챙겨 오고, 팀이 확인 중인 문서가 잠시 안 보이게 되면 이름을 보여 주고 먼저 묻는다
- **왼쪽 사이드바** — 팀 변경 상태 줄(앱이 켜져 있으면 창으로 돌아올 때와 10분마다 팀 저장소를 살펴보기만 하고,
  새 변경이 있으면 "팀에 새 변경 N개" 와 옆의 "받기" 단추로 알린다 — 한 번 누르면 받고, 저장 안 한 편집·안 올린 작업은 그대로 남는다.
  macOS 는 Dock 아이콘 배지에도 받을 변경 수를 띄우고 받으면 지운다),
  그 아래 "고친 문서 N개 · 팀에 확인 요청"(팀 최신을 먼저 받고, 안 올린 내 수정을 `app/edits-<시각>` 이름으로 올려 팀 저장소에
  PR 을 연다 — 합치기는 팀이 GitHub 에서 한다. 열어 둔 요청이 아직 열려 있으면 새로 고친 것을 거기에 더하고, 승인해 팀이
  확인 중인 위키화가 있으면 새 요청을 따로 열지 않고 그 요청에 더한다. 팀이 요청을 squash 로 머지하면 다음 받기가 들어간 것은
  팀 것으로 맞추고 그 뒤에 고친 것만 남긴다. 보낼 문서는 버튼에 올리면 보이고, 같은 문서를 둘이 고친 것을 고르기 전에는
  꺼져 있다. 받기 전 자동 저장은 받을 팀 변경이 있을 때만 한다. 앱 밖에서 새로 만든 문서는 저절로 실리지 않고, 그 아래
  "새로 만든 문서 N개도 함께 보내기" 를 고를 때만 `edit:` 커밋으로 함께 간다. 같은 문서를 둘이 고쳤으면 상태 줄 옆에
  "승인에서 고르기" 단추가 붙고, 누르면 받기 대신 승인의 고르기로 간다), 보관함 이름(아래에 전체 경로 한 줄),
  위 칸 글자 탭(파일 · 태그 · 북마크), 그리고 지식 관리·설정. 문서 자리가 아닐 때는 트리 위에 "문서로 돌아가기" 줄이 있다.
  태그 칸은 속성 `tags` 와 본문 `#태그`(코드·제목 줄 제외, 대소문자 무시, `#a` 는 `#a/b` 도 품는다)를 많이 쓴 순으로 세고, 누르면 `#태그` 로 찾는다 —
  검색창의 `#태그` 는 거르개라 `#회의 예산` 은 그 태그 문서 안에서 "예산" 을 찾는다. 북마크는 문서 위 ☆ 로 달고 떼며
  Obsidian 과 같은 `.obsidian/bookmarks.json` 에 둔다(그 파일의 검색·그룹 항목은 건드리지 않는다). 북마크 칸의 줄은
  바로 위 폴더와 이름을 같이 보여(`decisions · PLAN`) 이름이 같은 문서가 갈린다.
  글자 메뉴라 아이콘 뜻을 배우지 않아도 읽는다. 트리에서 오른쪽 클릭(또는 F2·Delete)으로 이름 바꾸기·휴지통,
  끌어서 다른 폴더로 옮기기. 새 노트는 이름부터 쓴다
- **웹 탭** — 빈 탭의 `웹 페이지 열기` 로 문서 자리 탭에 웹 페이지를 띄운다. 주소칸은 주소만 받는다(검색창이 아니다 —
  `example.com` 처럼 넣으면 https 를, `localhost`·IP 면 http 를 붙인다. http(s) 밖 주소는 열지 않는다). 탭 이름은 페이지 제목이고,
  다른 탭으로 가도 페이지는 살아 있다가 탭을 닫으면 사라진다. 페이지는 앱과 나눈 저장 구역에서 돌고(로그인은 웹 탭끼리 같이 쓴다)
  보관함·앱에는 닿지 못한다. 툴바는 뒤로·앞으로·다시 불러오기(불러오는 중엔 그만)·주소칸·`담기`·브라우저에서 열기다.
  `담기` 는 지금 그려진 페이지(스크립트가 그린 글·로그인 뒤 페이지 포함)를 서버에서 다시 받지 않고 자료(`Clippings/`)로 쓴다 —
  주소 넣기와 같은 변환·10MB 상한이고, 끝나면 "자료에 담았어요 · 열기" 가 뜬다. 못 연 페이지는
  실패 문구와 `다시 열기` 를, 멈춘 페이지는 "페이지가 멈췄어요" 를 보인다. 페이지가 새 창을 열면 새 웹 탭으로 열고, 파일 받기는
  기본 브라우저로 넘기며, 위치·알림·카메라 같은 권한은 묻지 않고 거절한다. 페이지에 초점이 있어도 앱 단축키(⌘W·⌘K·탭 이동 등)는
  앱이 받고, ⌘[ ⌘] 는 그 페이지의 뒤로·앞으로, ⌘L 은 주소칸, ⌘R 은 다시 불러오기다. 리더·분할·미리보기·채팅 답의 http(s)
  링크도 읽던 탭을 두고 새 웹 탭으로 열린다 — ⌘(Windows 는 Ctrl)을 누르고 누르면 기본 브라우저로, 메일 주소는 늘 메일 앱으로 간다
- **오른쪽 채팅 칸** — 탭 띠에 늘 있는 것은 채팅·위키 초안 둘이다. 참고한 페이지 탭은 근거를 열어 둔 동안, 기록 탭은
  기록을 보는 동안만 띠에 뜬다(기록 머리의 × 가 열기 전 탭으로 돌려보낸다). 문서를 보면서 묻고, 답의 근거는
  본문을 덮지 않고 옆 칸에 뜬다. 근거를 닫거나 머리의 "← 채팅으로"(연 탭 이름)를 누르면 열기 전 탭으로 돌아가고, 읽는 근거 칩은
  눌려 보인다. 다른 탭에 있는 동안 답이 오거나 와 있으면 채팅 탭에 점이 붙는다
- **좌우 분할** — 리더 머리의 "오른쪽에 열기"(또는 트리 오른쪽 클릭)로 문서 자리 오른쪽에 문서 한 장을 더 띄운다. 오른쪽 칸의 링크는 그 칸만 바꾸고, 그 칸에서도 편집·저장(`edit:` 커밋)한다. "가운데에서 열기" 로 옮기면 닫힌다
- **문서 기록** — 리더 머리의 기록 단추("이 문서의 기록")가 옆 칸 기록 탭을 열고 닫는다. 기록 탭은 지금 가운데 문서의 버전을 새것부터 띄우고 문서를 옮기면 따라간다(이름이 바뀌기 전 기록까지, 최근 200개). 줄마다 누가(AI가 씀 · 내가 고침 · `<GitHub 아이디>` 고침 · 로그인 전 앱 커밋은 "고침") · 언제. 버전을 누르면 리더 자리에 그 버전과 지금 글의 다른 줄이 "예전 글 / 지금 글" 로 뜨고(같은 버전이면 그렇다고만 한다), "이 버전으로 되돌리기" 는 그 버전 글을 편집 저장과 같은 길로 저장한다(`edit:` 커밋). 되돌린 뒤 리더 위 한 줄 알림의 "실행 취소" 가 되돌리기 전 글을 같은 길로 다시 저장한다. 비교는 버전을 고른 때의 글 기준이라, 보는 사이 문서가 바뀌면(받기·AI 가 씀) 되돌리기를 막고 "다시 견주기" 를 권한다. 승인을 기다리는 위키화가 있어도 막는다. AI가 씀 = 위키화 작업 브랜치에서 온 커밋, 채팅이 쓴 노트(`note:`), 위키화 에이전트의 결과 커밋(`feat:`). md 가 아닌 글자 파일(html·txt·json·코드)도 미리보기 머리의 기록 단추("이 파일의 기록")로 같은 목록과 줄 비교를 본다 — 비교만 하고 되돌리기는 없다(그림·PDF 에는 단추가 없다). 그런 파일은 글이 40만 자를 넘으면 줄 비교 대신 그렇다고 말한다
- **링크 칸** — 문서 아래에 여기를 가리키는 페이지, 링크 없이 이 문서 이름(제목·파일 이름)을 적은 곳, 가리킨 곳이
  없는 링크를 모은다. "링크 걸기" 는 그 자리 한 곳만 `[[ ]]` 로 바꾸고(코드·주소·이미 건 링크 안은 세지 않는다),
  "만들기" 는 그 이름의 노트를 만든다 — 둘 다 사람이 누른 편집이라 `edit:` 커밋이다. 점검에도 볼트 전체의 없는 링크가 뜬다
- **탭** — 문서 자리를 여러 장 띄운다(Obsidian 과 같다). 트리에서 ⌘ 누른 채 누르거나 가운데 단추로 새 탭,
  리더 본문의 링크와 ⌘K 에서 고른 문서도 새 탭에 열린다(읽던 글은 그 탭에 그대로 — 빈 탭이면 그 탭에),
  탭마다 보던 자리와 뒤로·앞으로 기록이 따로다. 마지막 한 장은 닫는 대신 비운다.
  이름이 같은 다른 문서를 같이 띄우면 탭에 바로 위 폴더가 붙는다(`decisions · PLAN`).
  빈 탭은 할 수 있는 일을 세운다 — 오늘 노트 열기(없으면 오늘 노트 만들기)·문서 찾아 열기·새 노트 만들기·이 탭 닫기
- **단축키** — ⌘T 오늘 노트, ⌘N 새 탭, ⌘W 이 탭 닫기, ⌘1–8·⌘9 탭 이동(9는 막탭), ⌘\ 채팅 칸 여닫기, ⌘J 묻기, ⌘K 페이지 이동, ⌘P 명령 팔레트, ⌘[ / ⌘] 뒤로·앞으로,
  ⌥⌘T 새 탭, ⌥⌘W 탭 닫기, ⌥⌘[ / ⌥⌘] 옆 탭
  (Windows·Linux 는 Ctrl). 글을 고치는 중에는 편집기가 이긴다 — ⌘K·⌘P·⌥⌘T/W/[/] 는 어디서든 열리고, ⌘1–9 는 편집 중에는 양보한다.
  ⌘P 에만 있는 명령: "아무 위키 페이지나 열기"(지금 페이지·INDEX 같은 구조 페이지를 뺀 위키 페이지 하나 — 잊고 있던 페이지 다시 보기)
- **macOS 창 닫기** — 창을 닫으면 숨긴다. 탭·채팅·쓰던 글이 그대로 남고, 진행 중인 작업·볼트 감시·팀 살펴보기도 그대로 돈다.
  ⌘W는 탭을 닫는다 — 창을 숨기려면 빨간 버튼·⌘H를 쓴다.
  Dock 아이콘을 누르면 같은 창이 돌아온다. ⌘Q·업데이트 "다시 시작" 은 앱을 끝낸다 — 저장 안 한 글이 있으면 숨긴 창을
  꺼내 먼저 묻는다. Windows 는 닫으면 끝난다
- **지식 관리** — 자료·검색·그래프·점검·승인을 한 페이지의 구역으로 모았다. 매일 쓰는 것이 아니다.
  사이드바 행 아래 줄이 쌓인 것을 풀어 말하고(`승인 대기 2 · 자료 3`), 구역 탭에도 그 수가 붙는다
- **자료** — 트리에서 고른 md·txt·이미지(png·jpg·jpeg·gif·webp·svg·avif·bmp)·소리(mp3·wav·m4a·ogg·flac·3gp)·영상(mp4·mov·webm·mkv·ogv)·PDF 를 문서 자리에서 미리 본다. 그림은 칸 너비에 맞춰 뜨고 위 단추로 `원본 크기`·한 단계씩 크게·작게(25~400%)·`맞춤` 을 오간다 — 그림을 누른 뒤 ⌘(Ctrl)+휠·⌘= ⌘- ⌘0 도 같다. 소리·영상은 재생·탐색까지 되고, 기기가 재생할 수 없는 형식이면 Obsidian 으로 보낸다. 노트 안 `![[파일]]` 도 같은 규칙으로 그린다. json 은 들여쓰기를 다시 매긴 원문(깨졌으면 원문 그대로와 그 사실), html 은 스크립트가 막힌 페이지 모양과 원문을 버튼으로 오간다. 워드(.docx)는 제목·목록·표·그림을, 파워포인트(.pptx)는 발표 순서대로 슬라이드마다 글과 그림을 한 장에 보인다(모양은 옮기지 않는다 — `기본 앱으로 열기`. 20MB 넘는 문서·읽지 못한 문서는 그렇다고 말하고 같은 단추를 준다). `.base`(Obsidian Bases)는 뷰마다 탭이 달린 표로 뜨고 이름 칸을 누르면 그 문서가 열린다 — 파일에 적힌 수식(`formulas:`)·정렬(`sort`)·묶기(`groupBy`)까지 계산한다. 이 앱이 모르는 조건(모르는 함수·표 아닌 보기)은 틀린 행 대신 이유를 보이고 Obsidian 으로 보낸다. `hasTag`는 속성 `tags`와 본문 `#태그`를 같이 본다(사이드바와 같은 집합)
- **설정** — Claude 연결, 모델 하나(목록에서 고른다 — 목록에 없는 이름은 고급에서), 보관함, GitHub 백업,
  라이트/다크 테마(재시작 후 유지), 화면 언어(한국어/English — 처음은 한국어, 고르면 바로 바뀌고 재시작 후 유지. AI 에게 보내는 지시와
  보관함에 쓰이는 글·기록은 화면 언어와 상관없이 그대로다), Obsidian으로 열기, 앱 업데이트, 보관함 상태 되돌리기. 개발자가 쓰는 것은 맨 아래 **고급** 에
  접어 둔다 — 모델 직접 입력(새 모델·Codex 모델 이름), MCP 서버(이름 +
  명령 한 줄 또는 https 주소, 서버 문서의 `mcpServers` JSON 붙여 넣기, 환경 변수 — 켠 것만 채팅 세션·선택 영역 고치기에 넘기고
  위키화·점검에는 넘기지 않는다), 내 Claude 설정(이 컴퓨터의 `~/.claude` 규칙·훅·스킬을 채팅에도 쓸지 — 기본 켜짐, 끄면 보관함 설정만),
  고급 표시, AI 프로그램 위치(설치 경로),
  화면 배치 되돌리기, 진단 정보(아래). 켜 둔 MCP 서버나 목록에 없는 모델이 있으면 고급은 펼쳐진 채로 열린다
- **진단** — 배포본에서도 main·화면 오류, 잡히지 않은 예외, 화면·보조 프로세스 종료, 1초 넘게 걸린 IPC 를
  `userData/logs/main.log` 에 남긴다(5MB 에서 돌려 3개까지 보관, 이 컴퓨터 밖으로 보내지 않는다). 토큰·비밀번호·MCP 환경 변수 값은 쓸 때 가리고
  홈 경로는 `~` 로 줄인다. 화면을 그리다 throw 하면 빈 창 대신 복구 화면(다시 열기·진단 정보 내보내기)이, 창 화면이 죽으면 main 대화상자가 뜬다.
  설정 › 고급 › 문제 해결의 **진단 정보 내보내기** 는 기록 파일과 앱·OS 버전, 허용 목록 설정(보관함 경로·GitHub 계정·MCP 명령과 env 는 빼고)을
  zip 하나로 저장한다 — 사용자가 그 파일을 팀에 보낸다. 같은 칸에서 진단 기록 폴더를 연다. 기록 본문의 보관함 경로는 `<vault>` 로 바뀐다.
  같은 칸의 **개발자 모드**(기본 꺼짐, 켤 때 main 대화상자로 한 번 묻는다)를 켜면 상세 기록(debug)이 남고, 배포본에서도 개발자 도구(⌥⌘I · Ctrl+Shift+I 또는 버튼)를
  열 수 있고, 프로세스별 CPU·메모리 표와 성능 기록(Chrome trace — 시작·멈추기, 경과 시간, 5분이면 저절로 멈춤)이 보인다. 성능 기록은 진단 기록 폴더에
  `trace-<시각>.json` 으로 최근 3개까지 남고 진단 정보 zip 에는 넣지 않는다(연 웹 페이지 주소가 들어 있어 보낼 때 직접 고른다). 꺼져 있으면 main 이 이 손잡이들을 거절한다

## 설치와 삭제

테스트용 비서명 빌드다 — 첫 실행은 mac 에서 `xattr -dr com.apple.quarantine "/Applications/2nd-brain.app"`
(또는 차단 뒤 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기"; 우클릭 → 열기는 macOS 15 미만에서만), Windows 에서
SmartScreen "추가 정보 → 실행" 이 필요하다. Claude·Codex CLI 는 설치본에 없고 첫 화면의 "설치" 버튼이 깐다.

- **mac**: dmg 의 앱을 `/Applications` 로. 삭제는 dmg 루트(또는 앱 안 `Contents/Resources`)의
  `Uninstall 2nd-brain.command` 를 터미널에서 `bash "<경로>"` 로 — 앱·앱 데이터·앱이 깐 CLI 를 확인 뒤 지운다
  (`--yes` 묻지 않음 · `--check` 지우지 않고 남은 것만 세기).
- **Windows**: `setup.exe`(per-user, 관리자 권한 없음). 삭제는 프로그램 추가/제거 또는 설치 폴더의
  `Uninstall 2nd-brain.exe` — 앱이 깐 CLI 가 있으면 같이 지울지 한 번 묻는다. 무인은 `/S`.
- **예전 이름(2nd-brain Desktop·eureka-wiki)으로 깐 경우**: 설정·대화·로그인은 그대로 이어진다(앱 데이터 폴더는 이름과 무관하게
  `2nd-brain-app`). 보관함 기록의 옛 이름 커밋도 계속 앱이 만든 것으로 보인다. mac 은 새 `2nd-brain.app` 이 옛
  `2nd-brain Desktop.app`·`eureka-wiki.app` 옆에 따로 깔리므로 옛 앱은 직접 휴지통으로 —
  옛 언인스톨러를 돌리면 앱 데이터까지 지운다. Windows 는 appId·설치 폴더(`2nd-brain-app`)가 같아 기존 설치를 바꿀 것으로
  본다 — 미검증, 첫 교체 설치 때 옛 바로 가기가 남는지 확인한다.

지우는 경로의 정본은 `build/uninstall-targets.json`, 절차·우회·수동 매트릭스·알려진 잔여물은 `docs/INSTALL-TEST.md`.
볼트 폴더와 앱이 깔지 않은 CLI·설정은 어떤 경로에서도 건드리지 않는다.

## 개발

```sh
pnpm install
pnpm dev        # 개발 창
pnpm test       # vitest
pnpm test:e2e   # build 후 Playwright (e2e/**/*.spec.ts)
pnpm build:mac  # mac arm64 dmg — ad-hoc 서명
pnpm build:win  # Windows 에서만(mac 크로스 빌드는 mac 용 git 을 번들한다) — CI installer 워크플로가 만든다
```

e2e 는 테스트마다 앱을 띄운다. 앱과 임시 폴더의 뒷정리는 spec 이 아니라 `e2e/fixtures.ts` 의 `launch`
fixture 가 한다 — 단언이 깨지거나 시간 초과로 끊겨도 닫고 지운다. 임시 폴더는 실행마다 한 그루
(`$TMPDIR/2nd-brain-e2e/<runId>`)라 `globalTeardown` 이 통째로 걷고, 하루 넘은 옛 그루는 다음 실행이
걷는다. 앱을 띄우는 spec 은 `@playwright/test` 대신 `./fixtures` 에서 `test` 를 가져온다.
`pnpm test:e2e:stray` 는 스위트가 끝난 뒤 남은 앱 프로세스를 센다(0 이어야 한다).

CI(`.github/workflows/ci.yml`)는 main 으로 가는 PR 과 main push 마다 macOS 러너 하나에서 build(typecheck 포함)·lint·
vitest·e2e(실패 spec 한 번 재시도)·남은 앱 프로세스 0 을 본다. Windows 는 아직 없다 — 설치본 스모크(`installer.yml`)만 돈다.
`e2e/perf-vault.spec.ts` 는 240쪽 합성 볼트에서 열기·편집·태그·언급·검색이 한 동작 2초(점검 10초) 안인지 잰다.
`KNOWLEDGE_VAULT=<볼트 경로>` 를 주면 그 볼트의 로컬 복제(`git clone --local`)로 잰다 — 원본은 열지 않는다.

앱은 사용자 PC 의 git·Python 을 쓰지 않는다. git 은 `dugite` 번들, 병합 전 검증은 vault-kit 의
`vault_verify.py`·`vault_volume.py` 를 옮긴 `src/main/verify/` 다. `pnpm test` 의 대조 테스트
(`vault-verify.test.ts`)만 개발 PC 의 `python3` 로 원본을 같이 돌려 판정이 같은지 본다.
